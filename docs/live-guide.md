# nod 0.6 — 日英ライブ相づち実験

**現在の既定は意味・音声・履歴の統合モデル（production）です。** Jevは反応の4分類ではなく、発話の働き・完結性・表出された態度を組み合わせた15種の意味フレームを観測します。音声と統合した30状態の分布から、頷きや短い表情を選択します。式と理論上の根拠は [production-design.md](production-design.md) を参照してください。

画面に「意味・音声・履歴の統合モデル」と表示されます。旧4分類方式は`--response bayes`、旧混合モデルは`--response responsive`で再現できます。

配置先は `C:\Users\kosuk\nod`。ローカルCPUで音声認識と反応機会を推定し、Jevに意味フレームを問い合わせ、PCアバターが応答します。今回の実装・検証対象はPC版です。

## プレゼン練習

`start-presentation-en.cmd`（英語）/ `start-presentation-ja.cmd`（日本語）も統合モデルで起動します。通常の起動と同じです。旧文区切り拡張を比較する場合だけ`--response presentation`を指定します。旧方式は [research-v2.md](research-v2.md) に記載しています。

新研究条件はASR確定理由を記録し、12秒上限や入力停止から終了後反応を追加しません。旧ログの終了理由を推測して埋めることもしません。

## 最初の起動

`start-ja.cmd`（日本語）または `start-en.cmd`（英語）をダブルクリックします。モデル読込後に既定ブラウザが開きます。最大5分で終了し、画面の「セッションを終了」でも停止できます。終了済みの動作履歴はJSONLに残ります。

PowerShellの場合:

```powershell
Set-Location C:\Users\kosuk\nod
.\.venv\Scripts\python.exe -m nod live --language ja --open-browser
# 英語は上の ja を en に置換
```

マイクが違う場合は一覧を確認して番号を指定します。一覧表示だけでは録音しません。

```powershell
.\.venv\Scripts\python.exe -m nod audio-devices
.\.venv\Scripts\python.exe -m nod live --language ja --device 1 --open-browser
```

`--seconds 60` は1分、最大1800秒。`--dashboard-port 0 --port 0` は競合しない空きポートを使います。画面はloopback限定。セッションごとに言語を選ぶ方式で、発話内の言語自動切替には対応しません。

### 旧v1/v2の調整履歴（現在の既定とは異なる）

旧v2は **意味反応あり v2 / responsive** です。VAPの閾値は0.40で、反応機会が成立した後の意味判定にVAPスコアを再度掛けない方式としました。動作後は1.8秒休止します。

v2では、Jevの分類確率にASR信頼度を掛け、残りを過去の判断で補う混合方式へ変更しました。これは元のベイズ更新の不具合修正ではなく、別のモデルへの変更でした。現在は比較条件として保持します。旧版のログは当時の式で再生します。

小さいうなずきのアニメーションは従来と同じです。「理解」は強調度未接続でも深めのうなずき、「共感」は軽く首を傾ける表情に分けました。感情の喜怒哀楽を推定した表情ではありません。強調度による可変強度はACN接続後の課題です。

VAPの機会とは別に、発話とその意味評価が両方確定し、理解または共感の確率が0.65以上・次点との差0.20以上・ASR信頼度0.65以上・調整後の確率0.50以上なら、発話終了後の受け止めを許可します。音声ストリームが現在も届いていること、意味が新鮮であること、動作後1.8秒の休止を満たす必要があります。同じ発話への理解・共感は最大1回。沈黙だけ、小さい相づちだけの意味判定、古い入力では追加しません。小さい相づちのあとに理解・共感が1回続く場合があります。

ログには `trigger: vap` / `utterance_end` を記録し、画面には後者を「発話確定後」と表示します。VAPだけの条件を調べる実験と、発話終了後の受け止めを含む実験は分けて比較してください。

従来の条件で比較する場合:

```powershell
.\.venv\Scripts\python.exe -m nod live --language ja --response conservative --open-browser
```

カスタム `--config` と `--response` は併用しません。カスタム設定はその値を尊重します。ログには適用した閾値・判断方式・休止時間を記録し、旧ログも従来の判断式で再生できます。

最初の実マイクログ約162秒では相づち1回、Jev判定採用69件でした。同じ認識・モデル出力を使い、動作ACKを模擬したオフライン比較では、新設定は5回になりました。新設定での実マイク計測や適切さの評価を済ませた数値ではありません。

上記はv1時点の比較です。続く約144秒のv1ログでは小さい相づち13回のみでした。同じ記録のv2オフライン比較では、小さい相づち14回・理解1回・共感1回。実時間の動作・自然さは再起動後の会話で評価してください。

音声のRMSが `0.012` を上回ると発話を開始し、600msの静けさで確定します。環境雑音が強い場合は `--rms-threshold 0.02`、小声の場合は `0.008` などを試し、使用値を実験記録に残してください。これは簡易な区間検出で、発話内容や感情を測る値ではありません。

## 画面と反応

- **発話内容をどう受け止めているか**：15種の意味フレームから計算した、発話の働き・内容のまとまり・語られた経験の態度。展開すると生の意味分布も表示します。
- **応答機能／信頼度を反映した判断**：意味分布から応答機能への対応と、ASR・経過時間・単位間履歴を反映した分布。実際の選択には音声を含む30状態の期待効用を用います。
- **反応可能性**：VAPスコア、意味上の完結性、安定した文境界、実際の静けさを統合した設計モデルの値。人手で校正された確率ではありません。
- **動作**：継続促進は小さな頷き、内容の受領は深めの頷き、個人的経験の受け止めは短い傾きとwarm／concerned／attentiveの表情。理解や同意を客観的に保証する表示ではありません。
- **待機理由**：意味評価待ち、認識の安定待ち、音声更新待ち、効用による待機など。同じ内容への受領反応は繰り返しません。

アバターは判断コマンドの可視化です。タイマー式コントローラのACKは画面描画や実サーボの開始時刻を測っていません。古い画面接続時に過去の動作を再演しません。

## ローカル処理とオンライン処理

ASRはfaster-whisper base / CPU int8、VAPはMaAI VAP-BCの日本語・英語各モデル / CPU、いずれも配置済みファイルから読み込みます。初期化時に重みを自動取得しません。Jevは `jev-1.13.0`、公式APIへ認識文と過去20秒以内の文脈を送ります。音声は送信しません。

キーは `.env` の `TYPESAFE_API_KEY` を読み、値は画面・ログに出しません。シェルとして評価せず、他の環境変数は取り込みません。環境変数に値があればそちらが優先されます。

ASRは原則800msごとの因果的な音声プレフィックスを処理し、1件の推論と最新の待機1件まで保持します。VAPは100msごとに別ワーカーで処理。入力・VAPが1秒以上遅れる、キューがあふれる、マイクの不連続を検出する場合は出力を止めてエラーを返します。

統合モデルのJevは同時1件、最新待機1件、期限1800ms、意味入力の鮮度3500ms。期限超過やAPIエラーは無反応へ捏造せず記録してバックオフします。認識修正・次発話への移行により古くなった結果は破棄します。カスタム `--config` を渡した場合はその期限を尊重します。

## マイクを使わない検証

合成音声を実時間で順に入力するテストです。スピーカーには再生せず、先の音声を読んで認識することもありません。

```powershell
.\.venv\Scripts\python.exe -m nod live --language ja --wav experiments/pilot/synthetic-ja.wav --open-browser
.\.venv\Scripts\python.exe -m nod live --language en --wav experiments/pilot/synthetic-en.wav --open-browser
```

`--semantic mock` はAPIを使わない固定確率の動作テストです。実モデルの意味精度評価には使えません。入力ファイルは16kHz・モノラル・PCM16のWAVに限定します。

## 実験の記録

`sessions/日時-live.jsonl` に発話、音声サンプル位置、推論時間、API結果、採用/破棄理由、動作を保存します。モデルのSHA256、言語、閾値、期限、合成/マイクの区別も保存。音声本体は自動保存しません。

```powershell
.\.venv\Scripts\python.exe -m nod analyze sessions/対象.jsonl --out sessions/summary.json
.\.venv\Scripts\python.exe -m nod replay sessions/対象.jsonl
```

`replay` はAPI・音声モデル・モーターを使わず、同じイベントから判断が完全一致することを検証します。まず各言語1分で入力レベル・認識誤り・反応頻度を確認し、その後に会話長、話者、音響条件を増やします。正解ラベルは人手で確認してから精度集計に使ってください。

2026-09-19の合成音声による実接続検証では、日本語は動作0回、英語は小さなうなずき1回。両方でJev応答を取得し、APIエラーなし、判断ログの再生一致を確認しています。短い合成音声であり、自然会話精度・マイクの実音声・30分連続動作・実機遅延は未評価です。日本語には「図書館」などの認識誤りがありました。

## スタックチャンへの接続

現段階ではPCがASR・VAP・Jev・判断を担い、M5Stackは表情・サーボを担う構成を想定します。モデル全体をM5Stack単体で動かす構成ではありません。

1. 使用中のファームウェア、M5Stack機種、サーボ型番、配線、可動範囲を確定する。
2. PC上のブリッジを `ws://127.0.0.1:8765` に接続し、USBシリアル等でM5Stackへ渡す。現在のWebSocketはloopback限定で、M5StackからWi-Fiで直接接続する設定ではありません。
3. `src/nod/resources/contracts.json` のhello・時計同期・action_command・controller_eventを実装する。`output/transport.py` のSimulatedControllerを通信の参照にできるが、実行開始・完了は実機の状態から返す。
4. 同じaction_idの重複実行を防ぎ、TTL切れを拒否し、通信断時に未実行コマンドを捨てる。角度・速度は実機で校正し、正規化intensityをその範囲内へ写像する。

ブリッジの接続試験は `live --external-controller --port 8765` を起動し、モデル読込後15秒以内に接続します。現在はサーボ用ブリッジと機種固有ファームウェアを実装していないため、このオプションだけで実機は動きません。PC版はそのまま先に実験できます。

ACNは実装参照が手元にありますが、推論用の学習済み重み・正規化情報・単語特徴抽出の組合せが揃っていません。現在は固定低強度として明示し、強調度を計測した実験とは扱いません。

モデルの再配置が必要な場合は `models-prepare --language ja`、続いて `models-prepare --language en`。実際に使用したリビジョンとハッシュは `models/local-audio/manifest.json` を参照してください。

統合モデルの人手評価・確率校正・比較実験は [semantic-evaluation.md](semantic-evaluation.md)、今回の検証結果は [production-validation.md](production-validation.md) を参照してください。
