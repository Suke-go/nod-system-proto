# プレゼン練習と比較実験 — research-v2 / nod 0.5

2026-09-19。研究課題は「同じ意味観測に対して、明示的な履歴の保持が応答の適切さを改善するか」。4状態は応答機能であり、ロボット自身の理解度や共通基盤の成立を計測した値ではない。ベイズ型更新、未校正のJevスコア、手動パラメータという位置づけは維持する。

## 今回の改善

| 起動時の `--response` | 意味の扱い | 発火機会 |
|---|---|---|
| `bayes`（既定） | 履歴あり・一般化ベイズ更新 | VAP + 静けさによるASR確定 |
| `bayes-no-history` | 同じ更新式・観測ごとに対称事前分布 | 同上 |
| `direct` | 履歴なし・信頼度で重み付けしたJev出力 | 同上 |
| `presentation` | `bayes`と同じ | 同上 + 安定した文の区切り |
| `bayes-vap` | `bayes`と同じ | VAPのみ |

研究用既定とプレゼン練習モードを分ける。`presentation`は別のベイズモデルではなく、行動開始の規則を追加した条件。Jevプロンプト、事前分布、時間遷移、閾値、効用、動作強度、動作後休止時間は`bayes`と同じ。

`start-presentation-en.cmd` / `start-presentation-ja.cmd`で起動する。通常の`start-en.cmd` / `start-ja.cmd`は引き続き`bayes`。

## プレゼン用の文区切り反応

理解・共感の観測があるのにVAP機会がない場合、次を全て満たす安定した文でも受け止めを許可する。

- 現在のASR文全体が安定し、末尾が `. ! ? 。 ！ ？`。`...`は対象外。
- 意味評価の対象文と現在の認識文が完全一致。区間はまだ確定していない。
- 生の特定機能スコア0.65以上、次点との差0.20以上、ASR信頼度0.65以上、現在のbeliefの該当成分0.50以上。
- 音声・意味の鮮度、接続、動作後1800ms休止の条件を満たす。
- 同一ASR区間で理解・共感の表出は最大1回。修正された文、未完成の句、曖昧な観測からは追加しない。

`trigger=stable_clause`として記録する。句読点はASRが推定した手がかりで、真の構文境界や発話終了の正解ではない。列挙、略語、引用、修正を含む文での誤反応と、相手が話し続けている間の適切さを評価する。原稿読み以外に自動的に一般化しない。新しい感情分類やランダム動作は追加していない。

## 終了理由の区別

音声区間の確定に`final_reason`を追加した。`silence`（600msの静けさ）、`max_duration`（12秒上限）、`input_end`（入力終了）を区別する。新しい研究条件で終了後拡張を許可するのは`silence`のみ。最大長による打切りや停止を「話し終えた」と扱わない。VAPの独立した機会は従来どおり評価する。

旧ログに終了理由がなければ`unknown`として集計し、研究v2の再計算で静けさを推測補完しない。旧設定のログ再生は旧挙動を維持する。旧ログと新ログの動作数の差をこの変更だけで品質改善と呼ばない。

## 履歴の効果を分離する

`bayes-no-history`は各観測で事前分布を固定の対称分布に戻す。それ以外の更新式、ASR信頼度、観測の重複置換、確定情報の反映、経過時間での減衰は同じ。これが履歴保持の主比較。

`direct`は $b=qC(r)+(1-q)\pi$ を使い、過去の分類結果を混ぜない。信頼度1ならその時点のJev分布をそのまま共通の効用表に渡す。これはベイズ型の積ではなく、明示的な対照モデルである。

両対照もJevには同じ直近20秒の文脈を渡す。「履歴なし」は**フィルタの履歴なし**であり、システム全体から言語的文脈を消すことではない。Jev文脈の効果を調べるには別要因としてプロンプト入力を変え、API観測を新しく取得する必要がある。

## オフライン比較と測定

```powershell
Set-Location C:\Users\kosuk\nod
.\.venv\Scripts\python.exe -m nod research-review sessions\対象-live.jsonl --out runs\review-v2-001
.\.venv\Scripts\python.exe -m nod research-score runs\review-v2-001\annotations.jsonl runs\review-v2-001\predictions-by-condition\bayes-no-history.jsonl
```

`conditions.json`は完全な設定、`comparison.json`は反応機能・発火原因・回数/分・命令上の動作時間・平均強度を保存する。実サーボの計測値ではない。同じ正解ラベル項目に対応する各条件の予測を`predictions-by-condition`へ分離し、人手ラベル入力前には予測を見せない。未確認のラベルから精度を算出しない。

主要比較は`likelihood_product_symmetric`対`bayes-no-history`。`direct`は意味モデル直接利用の比較。`presentation`対`likelihood_product_symmetric`は文区切り規則の効果を調べる別比較。更新式×事前分布、終了後拡張なし、確定反映なしの従来の比較も残す。

同じ動作制約は同じ反応回数を保証しない。頻度と動作量を共変量・副指標として報告し、十分なデータがあれば頻度を揃えた補助比較を用意する。代表要求の意味ラベルだけでは、実際の動作時点の適切さや自然さは測れない。

## 英語プレゼンログでの開発診断

`20260919-143643-764082-live.jsonl`（216.75秒、研究v1）では、小さい相づち21回・理解1回。採用された意味評価165件の最多クラスはCONTINUER145件、UNDERSTANDING14件、NO_BC6件。理解を選ぶ分布が得られてもVAP機会がなく抑制された例があった。

同じASR/Jev観測と模擬ACKで再計算すると、研究v2の通常条件は21回・理解1回、プレゼン条件は21回・理解2回。これは開発に使ったログ上の差で、実会話や楽しさの改善を実証していない。履歴なし・直接利用もこの記録では通常条件と同じ動作数だった。ベイズの優位性は依然として未確認。

## 次の実験

1. 新しい話者・原稿を開発用、校正用、評価用に分ける。英語の専門語のASR誤認識も別に評価する。
2. 言語別に、履歴あり/なしを同一音声・同一意味観測で比較する。同じ現在文に異なる前段をつける例、途中訂正、結論の反転、API遅延を含める。
3. プレゼンモードは通常モードとの別比較にする。楽しさ・聞いてもらえた感覚・意味の適切さ・タイミング・煩わしさを別々に評定する。反応が多いほど良いという採点にしない。
4. 人とのライブ実験は順序をランダム化/カウンターバランスし、同じ話者の反復を独立人数として数えない。人数はパイロットの分散と主要効果から設計する。
5. 同意を得た音声/映像が自然さ・タイミングの評価に必要。現在の自動ログは音声を保存しない。M5Stack実機の実行遅延も別途測定する。
