**nod 0.9.1：意味を捉えた後の内容受領とASR終端の修正**

今回の変更はJevの再学習・プロンプト変更ではない。意味観測の変数、Dirichlet観測密度、6状態ベイズ更新は0.9と同一で、意味を捉えた後の方策と入力ジョブ管理を修正した。通常の `start-ja.cmd` / `start-en.cmd` に適用される。実行中のセッションには反映されないので、終了後に起動し直す。

**局所内容の受領**

従来はASR信頼度をベイズ更新へ投入した上で内容受領に0.65の追加閾値を課し、音響タイミングが低い場合は意味のまとまりがあっても見送っていた。

現在の入力範囲と一致する新鮮な意味観測で、解釈可能性報告0.65以上、局所完結性0.65以上、理解の事後確率0.65以上、実質的応答要求0.65以下の場合、短い非言語の内容受領についてタイミング重みを `max(従来の音響重み, 0.85)` とする。この経路ではASR指標0.65の追加閾値を使わず、共通の最低入力品質とベイズ事後分布で知覚の不確実性を扱う。発話全体の終了まで待つ必要のない受領動作であるため、VAPの低さだけで抑えない。ただし新鮮な音響入力の到着は引き続き必要。

この0.85は期待効用の設計上の重みで、校正済み確率でも心理学の定数でもない。意味報告だけで直接動作する構造にはせず、期待効用・動作状態・同一内容への履歴・4回/15秒の上限を適用する。

小頷きが完了して150ms以上経ち、より新しい意味報告がある場合、内容受領も通常のクールダウン中の候補にできる。動作中は割り込まず、同じ内容単位の内容受領は一度だけ。質問・未完結・低い理解確信・失効した観測はこの経路で通過させない。肯定や同意の意味を保証するものではなく、実際の受け取られ方は実験で評価する必要がある。

**考え中の短い断片**

「あの」「えっと」「う」「で」「と」、英語の `um / uh / well / so` など、保守的なリストに一致するフィラーだけの範囲では反応を待つ。文全体の完全一致による出力側ガードであり、Jevの観測値や人の心理状態を書き換えない。「はい」「しんどい」「うれしい」、フィラーに続く内容のある文は対象外。この語彙ルールの網羅性・言語差・適切性は未検証。

**ASR終端ジョブ**

最新の部分認識を待つ1枠とは別に、最大2件の確定認識待ちキューを保持する。確定ジョブを同区間の新しい部分認識や次の発話開始で黙って上書きしない。全て同じ単一workerで処理する。過負荷時は古い確定ジョブを明示的な `final_queue_overload` 理由で落とし、キューを無制限に伸ばさない。確定処理の分だけ次の部分認識の待ち時間が増え得るので、queue_ageを記録する。

区間終端が分かった時点で `asr_boundary` を発行する。無音終端のみをタイミングの手掛かりに使い、最大長分割を無音・意味完結とみなさない。意味観測は作らず、次の発話開始で旧境界は失効する。

次の発話開始後に返る前の区間の確定結果は `asr_job: archived` にテキストを残し、現在の発話・信念・動作へ差し戻さない。したがって、前の区間の内容受領機会を全て回復する実装ではない。次回の実験では、失った区間末尾を実際に読み、Jevへの入力欠落と分類基準の問題を切り分けられる。`queued / started / delivered / archived / discarded / failed` とその理由・区間ID・音声時刻・処理時間を記録する。生音声や認証情報は記録しない。
