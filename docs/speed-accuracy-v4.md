# nod 0.9：認識遅延と意味に応じた反応の修正

PC版の既定は `listener_responsive_v4`。音声処理はローカル、意味分類だけJevを使用する。起動は従来通り `start-ja.cmd` / `start-en.cmd`。起動済みセッションは終了して再起動する。

## 遅れを分解して対処

自然発話ログ `20260919-170448-569818-live.jsonl` では、ASR推論の中央値697ms、95百分位1530msに対し、Jevの通信込み応答は中央値250msだった。音声入力区間末尾から意味結果の受信までは中央値1157ms。生音声を保存していなかったため、認識誤り率や「共感を求めた語」の実際の終了時刻はこのログから測れない。

同一の合成音声6本を各2回、単独で処理したCPU比較では、Whisper baseからSenseVoice int8へ変更すると、日本語中央値559→218ms、英語598→167ms。日本語CERは1/86→0/86、英語WERは0/39→1/39で、英語の差は cancelled/canceled の綴りだった。この少数の開発用音声から自然発話全般の優劣は主張しない。

SenseVoiceはローカルCPU4スレッド、400msごとに現在までの音声を処理する。真のストリーミングencoderではなく、最大12秒の因果的な入力区間を再認識する方式。実行中1件・待機最新1件に制限する。長い区間・CPU負荷による遅延は引き続き監視が必要。認識結果の安定部分は保持するが、訂正可能であり、確定した真実とは扱わない。

`--asr-backend whisper` で旧認識器を選べる。ライブ表示で使わない単語タイムスタンプはWhisperでも省略する。ASRの確信度はSenseVoiceから取得しておらず、現状の知覚指標は文字列の安定性・改訂頻度による未校正の代理指標。API確率と同様、認識の正しさとは同一視しない。

## 観測密度の修正

状態は従来通り6状態：未知覚、知覚済み未解釈、解釈済みの中立・肯定・否定・混合。P/U/Eの構造、範囲に対応づけた意味証拠、改訂と失効は維持する。

旧版の未学習Gaussian観測モデルでは、q(negative)=.86、q(neutral)=.14、他=0という報告が、対数比の距離計算によって中立寄りに解釈される場合があった。個々の文章へのキーワード規則では修正せず、分類器が報告する分布を受け取る密度を変更した。

K分類の報告qと、その軸の状態jについて、

\[
f_K(q\mid j,\kappa)=\operatorname{Dir}(q;\mathbf1+\kappa e_j)
=\frac{\Gamma(K+\kappa)}{\Gamma(1+\kappa)}q_j^\kappa.
\]

知覚指標r、解釈可能性報告u、4値のappraisal報告aを受け取り、条件付き独立という明示的な設計仮定で積を取る。未定義の軸は一様なカテゴリ潜在変数で周辺化する：

\[
O(r,u,a\mid P=0)=f_2(r\mid0)\bar f_2(u)\bar f_4(a),
\]
\[
O(r,u,a\mid P=1,U=0)=f_2(r\mid1)f_2(u\mid0)\bar f_4(a),
\]
\[
O(r,u,a\mid P=1,U=1,E=j)=f_2(r\mid1)f_2(u\mid1)f_4(a\mid j).
\]

ここで \(\bar f_K=K^{-1}\sum_j f_K\)。既定κは各軸1。数値計算時には確率を1e-6で床処理し再正規化する。κ=1なら未定義軸の混合は一様密度となる。意味情報がない場合は、その軸を観測更新から外す。中立という報告を「理解した証拠」と特別扱いしない。

\[
b_t(s)\propto O(y_t\mid s)\bar b_t(s)
\]

同じ内容範囲の改訂は最新パケットで置換し、重なるASR部分結果を独立証拠として累積しない。時間経過による遷移と失効も継続する。状態・期待効用に基づく判断はPCが実行する。分類器が動作を決める設計ではない。

これは正規化された報告密度を用いる**工学的な生成モデル**であり、心理学がDirichlet分布や数値係数を保証するという意味ではない。理論的参照は、[Kopp et al. (2007)](https://wwwhomes.uni-bielefeld.de/gibbon/Dafydd_Gibbon_Publication_PDFs/2007_Kopp_Stocksmeier_Gibbon_Incremental_Multimodal_Feedback.pdf) の知覚・理解・態度、[Schlangen & Skantze (2009)](https://aclanthology.org/E09-1081/) の逐次情報と改訂、[Meguro et al. (2010)](https://aclanthology.org/C10-1086/) の傾聴対話の確率的制御。原論文のモデルの再現・心理的校正済みモデルとは呼ばない。

## 反応を増やす条件と抑える条件

意味センサーの型は変更していない。appraisalは「話し手が表現した経験の意味づけ」であり、共感してほしい欲求の直接測定ではない。新しいrubricは、直前の感情を新しい話題へ転用せず、努力・準備という未完の句から成功や失望を予測しないよう明記する。明示された「しんどい」は理由が未完でも解釈できる。

- 小頷きが**完了した後**、新しい意味証拠が届いた場合は、通常の1800ms待機の途中でも150ms以上あけて表情へ更新できる。動作の重複実行、故障状態の無視はしない。
- 一般的な受け止め表情から明瞭な肯定・否定の表情への更新を許す。同じ内容に同じ方向の表情を繰り返さない。方向の変更には新しい分布の支持が必要。
- 小頷きの効用は、解釈済みで感情的な内容について0とし、汎用的な促しより内容に合う表情を選びやすくする。頷き一般に共感機能がないという心理学的主張ではない。
- 表情には現在の意味報告でも非中立の質量0.65以上を要求する。古い喜びの信念だけで新しい中立内容へ笑顔を出さない。
- 同じ内容の小頷きの反復、意味に応じた反応を出した後の同一単位の小頷き、根拠が1200msより古い小頷きを抑える。全体の4回/15秒の上限は維持する。
- 表情動作は1000ms、強度0.3–0.55。係数・効用は開発用設計値で、参加者データから学習した方策ではない。

## 計測と校正

ログには音声サンプル範囲、ASR開始・推論時間・待機時間、意味要求元時刻、意味結果、状態分布、動作の根拠を記録する。ブラウザが表示中ならanimation frame callbackの受領も記録する。`dispatch_to_receipt_ms`は描画コールバックと戻り通信を含み、画面の光学的な表示開始時刻ではない。タイマー型コントローラのACKとも別に扱う。

`research-review` は、観測した報告分布と判断対象を分離して出力する。レビュー済みcalibration splitの各状態8件以上から、`listener-fit`で3軸のκを制約付き最尤推定できる。状態ラベル、モデル名、prompt SHA、密度族を検査する。旧Gaussian校正ファイルはv4へ流用できない。現時点の本番設定は `designed_unfitted` のまま。

次の自然発話評価では、同意を得て録音した別セッションを使い、①ASRのCER/WERと否定・主語・経験の取り違え、②意味手掛かりの時刻から表示までの遅延、③相応しい反応の見逃しと先走った反応、④聞かれている感覚を分けて測る。話者・セッション単位で開発／校正／評価を分離する。今回の合成音声・固定ログ再計算は、この参加者評価の代わりにはならない。

## 再現と切替

```powershell
# 既にこのPCには導入済み。環境を再構築する場合の追加依存と重み
.\.venv\Scripts\python.exe -m pip install "sherpa-onnx==1.13.8" "sherpa-onnx-core==1.13.8"
.\.venv\Scripts\python.exe -m nod sensevoice-prepare
# v4 + 旧音声認識器で比較
.\.venv\Scripts\python.exe -m nod live --language ja --asr-backend whisper --open-browser
# 0.8の状態更新・方策を使用
.\.venv\Scripts\python.exe -m nod --config configs/listener-v3.json live --language ja --asr-backend whisper --partial-ms 800 --open-browser
```

旧版の観測・方策はバージョンごとに残す。SenseVoice重みは[公式Sherpa-ONNX配布](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)の固定アーカイブとファイルSHAを検査して使う。推論時のダウンロードは行わない。
